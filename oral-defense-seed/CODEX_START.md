# 開発の開始指示

1. [ADR](docs/adr/0001-coach-led-shadowing.md)、[設計](docs/DESIGN.md)、[実装計画](docs/IMPLEMENTATION.md)、[受け入れ条件](docs/ACCEPTANCE.md)を読む。
2. 主経路はCoach主導シャドウイング。お手本正常再生完了で参照文を返答として確定し、自動で次の応答へ進める。録音・評価・毎回の承認は条件にしない。
3. 自由発話は今回のMVP後（#8）。実装時は発話終了後の最終transcriptを返答にし、厳密な発音評価を省く。dictationは別の文字入力練習。
4. 採用文の公開とCoach私的履歴を分離。イベントの所属・版・重複を検証し、遅れた通知で進行しない。
5. 既存構成で標準ループを先に成立させ、資料取り込み・自由発話を段階的に追加。
6. 未校正GOPを発音正解率にせず、音響未達で会話開発を止めない。P0の事実・未確認を分ける。
7. 実装と検証完了を区別し、起動手順とVALIDATION.mdを実測に応じて更新する。
8. 着手時に[計画レビュー](docs/REVIEW.md)のRV01〜RV07とIMPLEMENTATIONの対応時期を確認する。関連機能の変更時に必要なリファクタリングと回帰試験を行い、担当Issueへ証拠と未達を記録する。closedのDB子Issueだけを受け入れ合格の根拠にしない。

ローカル利用を基本とし、資料送信先は設定したproviderを使う。UI移行や評価器の採用は別の技術判断であり、本書では確定していない。
